## 0. 结论速览（TL;DR）

1. **该加，但只加"目标专属的输入侧载荷开关"，不加"机制开关"。** 小猫之神预设里共清点出 **66 个可开关项**（清单 A 顶层设置 12 项 + 清单 B SPreset 配置 18 项 + 清单 C 条目/正则 32 项 + 清单 D 工具层 4 项，另有体验向条目若干未编号），其中真正需要用户在 NyaaChat 里按模型目标选择的只有 **7 个**（每目标 3 个专属 + 1 个两目标同名）；另有若干项建议「内置固定」随目标自动生效；**其余约 50 项**应分别落到「正则层 / RosettaStone / 世界书 / 角色卡」或**不暴露**（见 §5）。
2. **建议暴露清单（默认值：开/关）**
   - 目标 `gemini25pro31pro`（对应 4.0test）：`identityCard`（身份卡·SoliUmbra，**开**，可编辑）、`refusalImmunity`（拒绝免疫开场，**开**，可编辑）、`disclaimerSpell`（防截断·免责声明咒语，**关**）
   - 目标 `gemini37flash`（对应 3.7f）：`dualModelCard`（双模型卡，**开**，可编辑）、`toolChannel`（game_content 工具通道强制输出，**关**，**依赖改造 M2、非开箱即用**）、`unicodeEncoding`（敏感内容 `\uXXXX` 编码规避 + 响应侧解码，**关**）
   - 两个目标各一份：`traceCleanup`（思维链痕迹清理：CoT 不回传 + 标签转义，**开**）
   - 合计 **7 个开关条目**（`traceCleanup` 两目标同名同实现）。它们的文本载荷默认值直接取自两份预设的 `enhanceDefinitions` / `nsfw` / `防截断` / `防截断2.0` 原文。
3. **三类"看起来该有、实际做不了"的开关必须明确不做**（否则 UI 会骗人）：
   - **预填类**（`预填-和小猫之神聊天`、`reasoning` 预填、assistant 预填尾）→ NyaaChat 无 prefill 通道（`api.ts:382-392` 请求体只有 `model/messages/stream/stream_options/tools`；**Q1/Q2 均已确认**）；
   - **停止串类**（`<end>`）→ 同上，请求体不带 `stop`，且 SPreset 侧 3.7f 本来也没生效；
   - **结构改造类**（伪 JSON 会话、`<|check|>` 收尾、世界书搬运、绝对注入 depth=0）→ 依赖 SPreset 的 ChatSquash / 后缀脚本，与 NyaaChat「动态尾部只有一条 system、Gemini 折进最新 user」的不变量正面冲突（详见 Q1）。
4. **落位主线（已按 Q1 硬约束 3 收敛，见 §6.4）**：**所有载荷统一落在 E1 = 那条唯一尾 system 里的独立新块 `<answerer_bypass target="…">…</answerer_bypass>`**，并把该块名**无条件**写进 `SESSION_PROTOCOL_ANCHOR`（即使某轮没有该块，静态前缀字节也不变）。**绝不能新增第二条 trailing system**（`chatPipeline.ts:505-510` 的不变量 + `api.ts:62` 在"末两条相邻都是 system"时拒绝折叠）。选 E1-first 的理由：新块位于缓存断点②之后，用户切换目标/开关只改尾部字节，**历史前缀缓存不受影响**；而"P37 目标放静态前缀（复刻 `systemInstruction`）"的原始方案会把载荷写进静态前缀，每次改动都击穿整段前缀缓存 —— 见 §6.4-K1（**这是本报告与 Q1 的唯一实质冲突，已显式收敛**）。
5. **数据结构**：只在现有单选框上**加法**——`bypass.answererFlagalac` 从 `{ target }` 扩为 `{ target, perTarget: Record<targetId, { options: Record<string, boolean>; templates?: Record<string,string> }> }`；开关项清单作为 `FlagalacTemplates.ts` 的 `options` 数组（唯一事实来源）；读取统一走 `resolveFlagalacOptions()` 收敛（未知 id / 非布尔 / 已下线目标一律丢弃）；`settingsBackup` `EXPORT_VERSION 7 → 8`（含校验+回填）；`App.tsx` `SCHEMA_VERSION 9 → 10` + `migrateV9ToV10` 补 `perTarget: {}`。
6. **顺手发现的两处既有风险**（不在本任务范围，但与本模块直接相关，属于"落地前必须先定"）：
   - **R1｜导入备份会让已下线的 ClavisSalomonis 复活且无 UI 可关**：`App.tsx:123-131` 的 v7→v8 迁移强制 `bypass.enabled=false`，但 `settingsBackup.ts` 的导入回填**没有**做同样的事（`settingsBackup.ts:419-468` 只补子对象），导入后由 `App.tsx:756` 以 `_version: 9` 落盘 → 之后再也不会走 v7→v8 分支。于是 `bypass.enabled:true` + `customTemplates.disclaimer` 会每轮注入前缀，而 BypassModal 里该模块已被注释隐藏（`BypassModal.tsx:467-610`）。
   - **R2｜同一 identifier 在两份预设里内容不同**：`2f2729f4`（P4=防截断 disclaimer 咒语 / P37=防截断 censorship_bypass 编码规则）、`3df19ba7`（P4=瞬发防输入截断 / P37=世界书设定捏）、`91918c0a`（P4=assistant 预填 / P37=`<|no-convert|>`）、`820a1944`（P4=`<|check|>` / P37=继续上文创作）。**任何"按 identifier 映射预设条目"的代码都必须带 preset 维度**，否则会静默张冠李戴。

**关键映射结论（v2：已按 Q1 硬约束 3 收敛为 E1-first）**：
- **原始观察（✅ 有预设策略支撑，保留作保真度依据）**：
  - **P4（gemini2.5pro & 3.1pro）**：预设刻意让首条为 user、把规则挤进 user/model 轮次（`.ref` 报告 §4.3/§4.9）。NyaaChat 侧 Gemini 走 OpenAI 兼容端点（`api.ts:201` 注释、`api.ts:526-535`），`foldTailSystemIntoLatestUser()`（`api.ts:58-95`）会把**动态尾部折进最新 user** —— **这正是"破甲文本搭用户消息的车"** ⇒ P4 目标的载荷天然属于 **L2/E1**。
  - **P37（gemini3.7flash）**：脚本把全部前导 system 合并成**唯一一条** system 消息，使其成为 `systemInstruction`（`.ref/SPreset` §6.2）⇒ 若要"通道保真"，P37 目标的载荷应落 **L1 静态前缀**。
- **收敛后的推荐（v2）**：**P37 目标同样落 E1**。理由：① Q1 硬约束 3 明确"破甲载荷唯一推荐落点是 E1"；② 落 L1 会让"切换目标/开关/编辑文本"这类用户操作**翻转静态前缀字节、击穿整段前缀缓存**（标准 §7.4），而落 E1 只动断点②之后的尾部；③ 双模型卡的破甲机理（身份隔离 + 角色语域锚定）主要靠**文本内容**而非通道特权，A/B 验证（V10）通过后再考虑升级到 L1。
- 两种落位都**不需要**新增 trailing system；E1 只是并入现有唯一尾条。

### 6.2 授权锚点写法（易漏；Q1 硬约束 3）
`SESSION_PROTOCOL_ANCHOR`（`chatPipeline.ts:310-314`）目前只声明了 `<session_rules>` / `<search_context>` / `<memory_context>` 三类块。若 Flagalac 载荷以**新标签**（建议 `<answerer_bypass target="…">…</answerer_bypass>`）进入 E1，必须：
1. 在锚点里补上该块的声明（说明其来源与效力）；
2. **无条件写入** —— 即使某轮没有该块（用户选了「无」、或所有开关都关）也要保留这句声明。锚点属于静态前缀，条件化会让前缀字节随轮次变化、击穿缓存（Q1 硬约束 3；标准 §7.1/§7.4，`chatPipeline.ts:436-441` 已有同样的"锚点恒定"注释）。

替代方案：把载荷并入 `<session_rules>` 内部作为一个子块 —— 优点是自动继承调解条款与授权；缺点是它会挤进"场景规则"语义（调解条款说的是"叙事走向以用户最新发言为准"，与破甲语义不搭）。**推荐前者（新标签 + 锚点无条件声明）**。另需注意：**不能复用 `bypassTemplates.injectBypassPrompts()`**（Q1 硬约束 7：该链路插在静态前缀 index 1 且受 `bypass.enabled` 门控），AnswererFlagalac 必须与 RosettaStone 同构、另起独立块。

**K1（唯一实质冲突）——"P37 目标落静态前缀" vs Q1 硬约束 3**
- 冲突点：v1 基于通道保真度建议 **P37 目标的 `dualModelCard` 落 L1 静态前缀**（理由：P37 脚本把全部前导 system 合成唯一 system 消息 → 进 `systemInstruction`，`.ref/SPreset` §6.2 有源码级证据）。但 Q1 硬约束 3 要求"避免设计会改变静态前缀的开关"，因为静态前缀必须跨轮逐字节稳定（标准 §7.1/§7.4；`chatPipeline.ts:436-441` 注释同义）。**只要载荷落在前缀，用户一旦切换目标/开关/编辑文本，整段前缀缓存即失效**；再叠加"同类条目按用户顺序、不做二次排序"（标准 §7.6）的要求，前缀类载荷还会与 persona/世界书抢位置。

## 7. 数据结构与持久化

### 7.1 `FlagalacTemplates.ts` 扩展（唯一事实来源）

```ts
export type FlagalacOptionLayer =
  | "input-structure"   // 位置/结构（本版不暴露）
  | "identity"          // 身份重定义
  | "output-channel"    // 输出通道
  | "anti-truncation"   // 防截断
  | "trace-cleanup";    // 痕迹清理

export interface FlagalacOption {
  /** 持久化键：写入 answererFlagalac.perTarget[targetId].options[id]。发布后不可改。 */
  id: string;
  /** 开关行显示名。 */
  label: string;
  /** 一行说明（保持简短）。 */
  description?: string;
  /** 新建 / 重置时的默认值。 */
  defaultEnabled: boolean;
  /** 作用层级：仅用于 UI 分组与文档，不参与运行时逻辑。 */
  layer: FlagalacOptionLayer;
  /** 默认载荷文本；有此字段的选项在 UI 上多一个「编辑 / 重置」。 */
  template?: string;
  /** 该选项在当前版本是否真正生效；false = 依赖项未就绪，UI 置灰。 */
  available?: boolean;
  /** 未就绪原因（置灰时的提示文案）。 */
  unavailableReason?: string;
}

export interface FlagalacTarget {
  id: string;
  label: string;
  description?: string;
  /** 该目标专属的开关组；缺省 = 该目标无开关。 */
  options?: readonly FlagalacOption[];
}

export const FLAGALAC_NONE_ID = "none";

/** 收敛：未知/非法输入一律回落到声明过的默认值，绝不留下"选不中"的状态。 */
export function resolveFlagalacOptions(
  targetId: string,
  raw: unknown,
): { options: Record<string, boolean>; templates: Record<string, string> };
```

`resolveFlagalacOptions()` 规则（**读取时收敛，不写回**）：
1. `targetId === "none"` 或未知目标 → 返回 `{ options: {}, templates: {} }`；
2. 只接受该目标 `options` 里声明过的 id；**未知 id 静默丢弃**（对应"下线某个开关"）；
3. 非布尔值 → 用 `defaultEnabled`；缺键 → 用 `defaultEnabled`（**因此新增开关不需要任何迁移**）；
4. `templates` 仅在"声明了 `template` 且值为非空字符串且 ≠ 默认文本"时保留，避免备份膨胀。

### 7.2 `BypassSettings` 形状草案（`src/types.ts:124-126` 扩写）

```ts
answererFlagalac: {
  target: string;
  /** 按目标 id 分别保存：切换目标不丢配置。
   *  已知 id 之外的键在读取/导入时被丢弃（与 target 的收敛策略一致）。 */
  perTarget: Record<string, {
    /** 开关值：缺键 = 用 FlagalacTemplates 里该 option 的 defaultEnabled。 */
    options: Record<string, boolean>;
    /** 仅保存被用户改过的载荷文本；缺键 = 用模板默认文本。 */
    templates?: Record<string, string>;
  }>;
};
```

**默认值**（`App.tsx` `DEFAULT_SETTINGS.bypass`，`App.tsx:440-444`）：

```ts
answererFlagalac: { target: FLAGALAC_NONE_ID, perTarget: {} },
```

理由：默认 `none` + 空 `perTarget` 时，Flagalac 完全惰性（不产生任何注入），与现有默认保持一致；各开关的默认值只在 UI 首次展开时由模板给出（**不落盘**），这样默认值将来可改而无需迁移。

### 7.3 切换模型目标时旧选项如何处理 → **保留（perTarget 按 id 分开存）**

- 两目标差异极大（P4 是身份卡+声明，P37 是双卡+工具通道），共用一套 `options` 会导致"切到另一个目标后开关值语义错位"；
- 用户在 2.5p/3.1p 与 3.7f 之间来回切换是常态（同一渠道不同模型），**重置会丢配置**；
- 不要的配置清理方式：从 `flagalacTargets` 里删除目标 → 下次读取时该键被丢弃（与 `resolveFlagalacTarget()` 的既有语义一致，`FlagalacTemplates.ts:69-76`）。**文档里要写明"下线目标 = 丢弃其配置"**。
