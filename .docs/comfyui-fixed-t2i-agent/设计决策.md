# COMFYUI_FIXED T2I Agent — 设计决策记录

> 本文件记录设计审核阶段确认的关键决策。SSOT 计划见 `开发计划-SSOT.md`。
> 初始设计见 `V1初始设计.md`。所有本功能文档均置于本目录。

## 背景

为 NyaaComfyUI（`comfyui-fixed`，付费图包节点）设计一套**独立的画图提示词生成 agent**，将提示词生成从"机械翻译/截断拼接"升级为"结构化分析 + 分段自然语言生成"，由**部署方**承担 agent 的 LLM API 成本，做出优于第三方 API / 用户自定义 ComfyUI 路径的画质，形成付费吸引力。

## 三路径边界（已在代码中拆分）

| 路径 | provider.kind | 提示词生成方式 | API 密钥 |
|------|---------------|----------------|----------|
| QinyAPI / OpenAI | `qiny` / `openai-custom` | `buildImagePrompt` 字符串拼接（硬截断 600 字符） | 用户自己 |
| 自定义 ComfyUI | `comfyui-custom` | `buildEnglishComfyPrompt` → 用户对话 LLM 翻译 | 用户自己 |
| **NyaaComfyUI（本设计）** | `comfyui-fixed` | **新 agent**（结构化 + 分段生成） | **部署方** |

## 关键决策点（用户已拍板）

### 决策 1：服务端 LLM 代理落点 = ext-host ✅

**问题**：agent 用部署方密钥（`COMFYUI_FIXED_T2I_AGENT_API_APIKEY`），绝不能进前端 bundle。当前脚手架 `buildFixedComfyPrompt` 仍在浏览器直接调 LLM，对 FIXED 路径不成立。

**决策**：在 `ext-host`（Node 原生 HTTP 服务）新增服务端代理端点，复用现成的 `proxyTts` 模式（`ext-host/src/server.js:122`）——无密钥请求进 → 服务端从 `process.env` 注入 key → fetch 转发 deepseek → 回传。

**理由**：
- ext-host 已有逐行可复用的 `proxyTts` 原型（注入 Bearer + fetch 外部 + 流式透传）。
- 与主 `docker-compose.yml` 同项目、同 `.env` 上下文，加三条 env 即可，无需碰 `NGINX_ENVSUBST_FILTER`。
- nginx 已有 `/api/ext-host/` 代理（`nginx.conf:188`）。
- 是 Node，可承载完整 agent 编排（结构化、分段、软字数控制、错误回退），纯 nginx 反代做不到。

**否决方案**：
- 纯 nginx 反代：无法改写 JSON body（model 注入不了）、外部域名 resolver/Host/URI 拼接易踩坑、承载不了 agent 逻辑。
- shared-server：职责错配（有状态账号/角色 DB），且它读独立 compose 的 `.env`，跨项目摩擦。

### 决策 2：model 由服务端强制 ✅

**决策**：agent 使用的 model（`COMFYUI_FIXED_T2I_AGENT_API_MODEL`，当前 `deepseek-v4-flash`）由部署方在 `.env` 固定，ext-host 端点从 `process.env` 取，**前端完全不感知、不可覆盖**。前端请求 body 只带 `messages`，不带 model / key / baseURL。

**理由**：部署方付费，需完全掌控成本与模型选择；这也是选 ext-host（node 可改 body）而非纯 nginx 的直接原因。

### 决策 3：单阶段 LLM 生成 ✅（V1）

**决策**：一次 LLM 调用完成。system prompt 内置结构化分析框架（多维度）+ 分段要求 + 软字数约束；user message 给场景上下文；LLM 直接产出**分段的英文自然语言提示词**。不做"先拆解 JSON 再生成"的双阶段。

**理由**：省钱、够用、延迟低。结构化拆解作为 system prompt 里的**思考框架**存在（引导 LLM 内部推理），而非独立的一次 LLM 往返。符合初始设计"LLM 对话本身不占用上下文，有足够区间做优质分析生成"的判断。

## 其他确认事项

### 开关暴露方式：vite define（非密钥布尔）

`COMFYUI_FIXED_T2I_AGENT_ENABLE` 是布尔开关，非密钥。采用与 `__COMFYUI_FIXED_NAME__` 一致的 vite define 注入前端（`__COMFYUI_FIXED_T2I_AGENT_ENABLE__`）：
- `true`：`comfyui-fixed` 路径走新 agent（前端 POST 到 `/api/ext-host/...`）。
- `false`：`comfyui-fixed` 路径回退到现有 `buildComfyPromptRequest` + 用户对话 LLM（即与 custom 路径同款）。

### 数据模型限制（影响 agent 设计）

`CharacterSettings` **无** personality / scenario 独立字段——人设全在单一 `description`；用户画像也是单一 `profile` 字符串。因此 V1 的"角色年龄/人种/身份/衣着/性格拆分"**只能靠 agent LLM 从文本语义解析**（作为 system prompt 的分析框架），不引入结构化字段。字段固化留给 V2 / AVG。

### 软字数控制（复刻 RosettaStone 模式）

把字数/分段要求写成**提示词文本**注入 system，**绝不对 LLM 输出做 slice**。目标参考 `TestPrompt.md` 实测值：**约 360 词 / 6 段落 / 每段 40-80 词**。输入侧（角色描述/历史/焦点消息）仍可 truncate 控制 token 预算。

### 命名订正

初始设计文档写 `COMFYUI_FIXED_T2I_API_ENABLE`，实际 `.env` 是 `COMFYUI_FIXED_T2I_AGENT_ENABLE`。**统一以 `.env` 为准**：
- `COMFYUI_FIXED_T2I_AGENT_ENABLE`
- `COMFYUI_FIXED_T2I_AGENT_API_BASEURL`
- `COMFYUI_FIXED_T2I_AGENT_API_APIKEY`
- `COMFYUI_FIXED_T2I_AGENT_API_MODEL`

### 流式：V1 用非流式

画图提示词是一次性产物，用户看进度条不看打字机。非流式（一次拿全文）更简单。ext-host 端点仍保留流式能力（proxyTts 现成），但 V1 前端按非流式消费。nginx 该端点超时需从默认 30s 提到 300s。

### 安全边界

- ext-host 新端点**只从 `process.env` 取 key/baseURL/model**，忽略 body 中任何密钥字段（proxyTts 现允许 payload 带 api_key，新端点必须收紧）。
- baseURL 服务端固定，不接受前端传 URL，避免开放中继。
- 图包计费（`consumeComfyuiPack`）逻辑不变，仍在出图成功后扣减。
