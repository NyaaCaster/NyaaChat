## 4. 已知问题与边界（必须随交接传递）

1. **装饰覆盖面**：仅 `p`/`li`/`blockquote`/`h1~h6`/`td`；**嵌套内联元素内部**（如 `<strong>“引用”</strong>`）不被装饰 —— 这是既有 `quote-highlight` 就有的行为，非本阶段引入。
2. **契约措辞**（已定稿，勿改错）：装饰 = **追加**，且实现必须是**两级节点**（正文=顶层 string、装饰=独立 Fragment）。**照"同置 Fragment"改会把 R2（引号高亮丢失）打回来**。
3. **启用开关不经插件配置通道**：`enabled` 属宿主/UI（`AppState.plugins[id].enabled`），`updatePluginConfig` 会**剥离** patch 里的 `enabled` 并告警。
4. **加载路径的归一化只作用于内存**，不写回存档（未知插件 id 会留在 IDB 里，但不可见、不可导出）。这是取舍，不是缺陷；"加载后写回"登记为**可选加固**。
5. **R4 保真度损失**：`PREFIXED_QUOTE_RE` 要求行首 ⇒ 单行中段 `猫娘:「…」` 的人名归属回落 `senderName`。**⚠️ 该引号仍会被装饰**，丢的只是归属，不是按钮。
6. **R3**：全角「：」不作前缀分隔符 —— 与 ST 原版一致，非本阶段引入。
7. **`ChatInterface.tsx` L1915** `messages.flatMap` 无元素级空值防护：单条缺 `id` 的畸形消息会整站白屏（生产消息都带 `id`）。**属既有代码，本阶段不修**（SSOT L10）。
8. **`t10` 保留 `failed` 状态**：它记录真实事实"第一次断环只断了一条边"；缺陷已由 **t12** 根除（叶子模块 + captain 独立探针：图入口先引插件模块时 `ids = ["quote-tts"]`、0 undefined 槽位）。看到 `t10 failed` + `t12 completed` 时**不要**当成未修复缺陷。
9. **团队 `Delivery: blocked`（记账项）**：`t10 failed without a follow-up repair`（t12 是 `implementation` 类型，无法与 t10 建立 repair 关联，因 captain 未持有 t10 的 finding id、不猜）+ `completed implementation has no passing review`（本阶段用 t7 独立验证，未建 `review` 类型任务）。**不影响交付**。
10. **`dev-server/` 的既有遗留**：其 nginx 模板仍含 `/api/ext-host/` 通配前缀与 legacy `= /api/openai/custom/generate-voice`，来自该独立仓库的首个提交，生产 `nginx.conf` 无此二者。
11. **dev 服要"听到声音"必须先配 TTS 上游**（否则点 🔊 得 `503 quote_tts_not_configured`，界面只闪一下 ❌、原因仅在浏览器控制台）：
    · 在 `dev-server/.env`（**本地、已 gitignore**）配 `PLUGIN_QUOTE_TTS_UPSTREAM_URL`，⚠️ **必须填基地址**（如 `http://host:5050`）—— `ext-host/src/server.js` L119 会自行追加 `/v1/audio/speech`；填成完整端点会让路径重复成 `…/v1/audio/speech/v1/audio/speech` ⇒ 上游 **404**（2026-09-15 实操踩到）。

12. **验收时的 `.quote-highlight` 读法**：计数 = 当前会话内**经过 `highlightQuotes` 的引号片段数（含被插件装饰的）**，每片段恰好 1 个；欢迎语自带的 `“…”` 也计 1，但**加载会话后欢迎屏被替换 ⇒ 跨会话不可相加**。判"装饰后高亮没丢"应在**同一会话内**前后对比，别比整屏总数。

## 5. 本阶段踩到并固化的方法学纪律（**接手者必读**）

本阶段出现 **六次"假通过/假发现"**，全部已写入 SSOT §11.5 / §11.13 / §12 L23：

1. **未跟踪路径上 `git grep` 必得 0** —— `plugins/`、`src/plugins/`、`.docs/plugin-system/`、`ExtensionsModal.tsx` 当前均未跟踪。残留/存在性检查一律 **`git grep` ∪ 文件系统扫描双方法交叉**。
2. **`git grep -E` 里的 `\|` 是字面竖线** —— 会让"期望 0 命中"假通过；多关键词用 `-F -e A -e B`。
3. **扫符号名之前先确认它没被改名/迁移** —— 用旧名扫新代码同样得到"假 0"。
4. **相对路径必须同时给出 cwd** —— 两处 `.ref` 目录内容不同，同一串相对路径在两个 cwd 下结论相反（R7 争议的根因）。
5. **"我重建过了"必须用证据确认** —— 全量缓存命中会让重建变成 no-op。判断镜像与源码的对应关系：优先"容器内 assets 文件名 + `index.html` 引用 + 产物内字面量在/不在"，时间戳次之。`docker image inspect` 的 `Created` 是 **UTC**。
6. **产物字面量 grep 的适用范围** —— 宿主写死的字面量（类名、告警/错误文案）压缩后保留、**可作正/反证据**；运行期拼接或压缩改名的（lucide class、局部变量名）为 0 命中**不代表功能缺失**，只能靠 DOM 断言。
7. **行数用 `(Get-Content <file>).Count`** —— `Measure-Object -Line` 会少算（实测差 5–22 行）。
8. **修一个缺陷时必须问"这会让哪些原本成立的断言失效"** —— 本阶段修好"正文消失"的同时把"引号高亮"打坏过一次（§11.12），而它不在当时的断言清单里。
