# UI交互设计要点
## 命名命题
- 项目中存在 CharacterLibrary 这个 共享角色库 系统，library 的命名后续可能造成语义分析冲突，建议使用例如 KnowledgeBase 的系统命名。

## 用户的知识库管理ui交互设计要点
- 入口：在对话主界面顶部工具栏的 `用户角色` 右侧 `正则` 左侧，加入 `知识库` 图标按钮，icon为 book ，点击后打开 知识库管理 界面。
- 界面主体：
  - 以卡片方式陈列知识库的库条目，整体结构接近 角色选择 及 聊天记录 这样的统一界面布局
    - 库条目卡片上要有编辑、删除两个图标按钮（与其他系统内容条目上的编辑、删除按钮保持统一），用户删除库条目时要二次确认提醒用户删除知识库后不可恢复，询问是否删除，确认删除按钮要用红色。
    - 库条目卡片上要显示这个库的token量计数显示。
    - 点击编辑按钮后进入这个知识库的编辑界面，后面的UI布局、使用交互沿用 NyaaLibrary-MCP 的结构和逻辑设计（考虑下知识库改名放在哪一级合适）。
      - 在 NyaaLibrary-MCP 原有基础上，要增加库内部界面中本库token量的计数显示。
  - 在顶部加一个和角色、聊天系统风格统一的 知识库用量 计量条，用户账号下可建立的知识库受到数量上限限制，默认允许建立5个知识库，沿用 共享卡槽 的设计，之后用代币猫粮来扩容，一次扩容提升1个知识库上限，费用在调研 共享卡槽 扩容费用后与我确认。在 共享账号 界面的 共享卡槽 下面加入 知识库栈 条目，显示账号的知识库上限和扩容按钮。
    - 补全之前系统缺少的设计：用户达到 共享卡槽 和 知识库栈 使用上限时，从共享角色库获取共享角色时，以及再新建知识库时，应该弹出提示窗口，分别告知用户已经达到 共享卡槽 或 知识库栈 的数量上限，询问是否要扩容，带有 取消 和 前往扩容 按钮，取消则关闭，前往则打开 共享账号 界面。
  - 需要一个新建知识库按钮用来给用户新建知识库
  - 需要一个 嵌入模型配置 的图标按钮，icon使用gear，点击后打开 嵌入模型配置 界面，提供 baseUrl 、apiKey、模型名 填写栏位，在apiKey填写栏右上角增加文本链接"获取嵌入模型" ，点击后以新页面跳转到 `https://cloud.siliconflow.cn/i/KJ0qgMuR`，模型名 填写栏位默认值预填`Qwen/Qwen3-Embedding-8B`，允许用户修改。
    - 这里帮我调研分析一下，本项目更适合`Qwen/Qwen3-Embedding-8B`还是`Qwen/Qwen3-Embedding-4B`
    - 用户如果没有配置过嵌入模型api，进入 知识库管理 界面时需要直接打开 嵌入模型配置 界面
    - 本界面需要一个 健康检查 按钮，用最低成本健康检查请求方式测试该api是否有效，检查检查失败弹出错误提示，要求用户修正配置，只有健康检查通过，保存设置 按钮才可成可点击状态，只要不通过，保存设置 按钮都是禁用状态。
    - 本界面需要保存设置按钮，关闭本界面时也进行自动保存。嵌入模型的api设置也需要加入 设置 系统的上传下载导入导出中。
    - 用户进行知识库的文档输入时，如果嵌入模型的api请求错误，需要弹出警告窗口告知用户嵌入模型API链接异常，询问是否要修改嵌入模型API设置，取消则关闭，前往修改则打开 嵌入模型配置 界面。
  - 因为知识库本身是服务器数据，不再需要类似角色、聊天记录系统的云上传下载功能
 
 ## 新建/编辑 规则条目中ui交互设计要点
 - 需要一个 `已关联知识库` 列表，以类似标签列表的方式显示出已经关联的知识库库条目，这时需要请求一下这个知识库的健康状态，如果知识库在服务端已经删除，这个库条目tag应该红色显示，保存条目编辑时如果有失效的知识库条目，则无法保存，并弹窗提示用户有失效的知识库条目，需要删除失效知识库条目后才能保存。
 - 需要一个 `关联知识库` 按钮，点击后列出该账号已有的知识库库条目（卡片方式，库条目卡片上要显示这个库的token量计数显示），让用户以勾选方式选择要关联的知识库，窗口有确定和取消按钮，关闭窗口则取消关联选择。
   - 如果账户下没有已经建立的知识库，则窗口中有一个 创建知识库 按钮，点击后先保存规则条目和角色，然后打开 知识库 管理界面。
 - 已经关联知识库的卡片上，KB徽标使用icon为 book ，与菜单栏入口按钮 知识库 的icon统一，提高用户认知关联性。

# 方案决策
- NyaaLibrary-MCP 项目只作为参考，不直接 fork ，所需逻辑本项目参照 NyaaLibrary-MCP 项目实现方案重写，源代码都在 H:\GitHub\NyaaLibrary-MCP 。
- 检索按推荐方案A：后端子服务只做纯粹的"给定 kbId + query，返回 chunks"，前端负责"激活→检索→注入"的编排，最小化对现有 pipeline 的侵入。
- 绝不做级联硬删：用户只能在 知识库管理 界面删除知识库库条目，不可以在此外任何界面（包括角色规则条目编辑知识库关联界面）中删除知识库。
- 加入知识库关联后，对话角色的数据结构就存在变更了，要注意图片模式导出导入角色卡时的结构更新，并且 SillyTavern 的角色卡没有这个结构，导出 SillyTavern 格式角色卡时需要清理这部分数据。
