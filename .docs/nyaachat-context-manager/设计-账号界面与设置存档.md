### 2.3 定案：方案 C

新增 `src/lib/settingsContext.tsx`：

```tsx
import React from "react";
import type { AppState } from "../types";

/**
 * Read/write access to the app-level settings for components that sit deep in
 * the tree and are mounted from many different parents.
 *
 * NyaaChat deliberately threads `settings` through props everywhere else, and
 * that stays the rule — this context exists for exactly one shape of problem:
 * a leaf modal (UserAccountModal) rendered from nine unrelated call sites,
 * five of which hold no settings at all. Prop-drilling it would mean adding
 * `settings` + `onSettingsChange` to four component APIs that have no other
 * use for them, plus their parents.
 *
 * Do NOT reach for this from components that already receive `settings` as a
 * prop — two sources of truth for the same value is exactly the bug this file
 * is shaped to avoid.
 */
export interface SettingsContextValue {
  settings: AppState;
  onSettingsChange: (next: AppState) => void;
}

const SettingsContext = React.createContext<SettingsContextValue | null>(null);

export const SettingsProvider = SettingsContext.Provider;

/** Null when rendered outside the provider — callers must handle that. */
export function useAppSettings(): SettingsContextValue | null {
  return React.useContext(SettingsContext);
}
```

`App.tsx` 的 `return (` 处（`:726`），把 `<>` 换成 provider：

```tsx
  const settingsCtx = React.useMemo(
    () => ({ settings, onSettingsChange: handleSaveSettings }),
    [settings],   // handleSaveSettings is stable enough — it only closes over setSettings
  );

  return (
    <SettingsProvider value={settingsCtx}>
      {/* …原有全部内容不动… */}
    </SettingsProvider>
  );
```

`UserAccountModal` 内：

```tsx
const settingsCtx = useAppSettings();
```

**9 处调用点全部不改**。`settingsCtx` 为 null 时（理论上不会发生，
`UserAccountModal` 只在 App 树内渲染）隐藏记忆行并 `console.error` 一次。

### 2.4 `useMemo` 依赖说明

`handleSaveSettings`（`App.tsx:669`）是每次渲染重建的普通函数，
但它只闭包了 `setSettings` 与常量，行为恒定。依赖只写 `[settings]` 是有意的：
把它加进依赖会让 context value 每次渲染都变，白白触发消费者重渲染。
**不要** 为此把 `handleSaveSettings` 包成 `useCallback` —— 那是另一处改动，
且它已被 8 个地方以 props 传出，改签名影响面更大。

## 3. 记忆行 UI

### 3.1 位置

`UserAccountModal.tsx` 的 `<Row label="注册时间">`（`:461-466`）**之后**、
`<Divider />`（`:468`）之前，即 identity 区块尾部。

不放进 economy 区块：记忆是能力开关不是额度，放在猫粮/卡槽之间会让人以为要花猫粮。

### 3.2 结构

```tsx

    {memoryEnabled && memoryUsage && (

    <button
      onClick={() => setIsEmbeddingOpen(true)}

      title="嵌入模型配置"
    >
      <Settings size={16} />
    </button>
    <MemoryToggle checked={memoryEnabled} onChange={handleToggleMemory} />
  </div>

```

- `Settings` 图标按钮样式对齐 `KnowledgeBaseModal.tsx:483` 的 titleAction 按钮
- 打开的是同一个 `EmbeddingConfigModal`，props `{ isOpen, onClose, token, onSaved? }`
- 用量数字**按万字显示**，避免 `1108000/2000000` 这种一屏数字。
  分母来自服务端 `quota`，不做膨胀折算（见 `设计-记忆生命周期与配额.md` §1.3）

### 3.3 开关组件

项目内无现成 switch 组件（`SettingsFormBits.tsx` 里是表单行而非开关）。
就地实现一个 20 行的小组件放在 `UserAccountModal.tsx` 文件内（不单独建文件 ——
只此一处使用）：

```tsx
function MemoryToggle({ checked, onChange }: { checked: boolean; onChange: () => void }) {
  return (
    <button
      role="switch"
      aria-checked={checked}
      aria-label="持久化记忆开关"
      onClick={onChange}
      className={`relative w-10 h-5 rounded-full transition-colors ${
        checked ? "bg-blue-500" : "bg-gray-300 dark:bg-white/15"
      }`}
    >
      <span
        className={`absolute top-0.5 left-0.5 w-4 h-4 rounded-full bg-white shadow transition-transform ${
          checked ? "translate-x-5" : "translate-x-0"
        }`}
      />
    </button>
  );
}
```

`role="switch"` + `aria-checked` + `aria-label` 是无障碍必需项，不可省。

### 3.4 未登录状态

`UserAccountModal` 未登录时渲染登录表单，不到 profile 区块，
记忆行**自然不出现**。无需额外处理。

```tsx
<ConfirmDialog

  message={

      <p className="text-amber-600 dark:text-amber-400">
        ① 提炼出的事实条目以<b>明文</b>存储在服务器上。聊天记录本身仍然端到端加密，但这些条目不加密 —— 服务端可以读到。
      </p>
      <p>② 提炼使用<b>你当前对话所选的模型</b>，消耗你自己的 API 额度。每次提炼都会提前提示，可以跳过。</p>

  onCancel={() => setMemoryDiscloseOpen(false)}

```

- **仅首次开启弹**。用 `settings.isMemoryEnabled` 从未为 true 判断不可靠（关掉再开就不弹了），
  故新增 `memoryDisclosureAcceptedAt?: number` 到 `AppState`：为 `undefined` 时弹，
  确认后写入时间戳。**这个字段进设置存档**（见 §6）—— 导入他人配置时不该跳过披露，

  账号界面里**没有当前对话上下文**，所以此处显示的是按 `EXTRACT_CHAR_CAP` 上界估算的
  「最多约 N tokens」，文案写「预估消耗约」时前面加「最多」二字。

`destructive` **不设为 true**：这不是破坏性操作，红色按钮会误导。

## 5. 关闭开关的处置（空洞 Q）

### 5.1 定案

**关闭开关 = 停止一切记忆行为，保留已有记忆，不自动删除。**

关闭后立即生效的四件事：

1. 不再触发提炼判定（`设计-提炼触发与状态机.md` §2 前置条件之一）
2. 不再调 `/memory/search`，不再注入 `<memory_context>`
3. 不再发送心跳 → 已有记忆最终由 TTL（90 天）回收
4. **已有的记忆分界线仍然显示，且发送裁剪仍然生效**

### 5.2 第 4 条是唯一需要解释的

分界线以上的轮次已经不在发送 history 里。关闭开关**不会**把它们放回去 ——
放回去会让下一轮请求突然膨胀数万 token，用户毫无预期地被计费，
而且可能直接超出上下文上限导致请求失败。

代价是：关闭开关后，那部分上文既不发送也不召回，等于真正遗忘了。
这必须在关闭确认弹窗里说明：

```tsx
<ConfirmDialog
  isOpen={memoryDisableOpen}
  title="关闭持久化记忆"
  confirmText="关闭"
  cancelText="取消"
  message={
    <div className="space-y-2 text-left">
      <p>关闭后将不再提炼新的记忆，也不再检索召回已有记忆。</p>
      <p>已归档的记忆<b>不会</b>被删除，重新开启即可继续使用。</p>
      <p className="text-amber-600 dark:text-amber-400">
        注意：已经归档的历史轮次不会重新加入发送内容 —— 关闭期间，记忆分界线以上的内容既不会发送也不会被召回。
      </p>
    </div>
  }
  onConfirm={confirmDisableMemory}
  onCancel={() => setMemoryDisableOpen(false)}
/>
```

关闭也要二次确认，因为它有上述不可见后果。**这一步用 `destructive={false}`** ——
数据没有丢失。

### 5.3 主动清空入口

记忆行下方（仅开关为开时显示）加一个文字按钮「清空我的全部记忆」，
`destructive` 的 `ConfirmDialog` 二次确认，调用新增端点 `DELETE /memory/all`。

这是"删除记忆"的唯一显式出口。理由见 `设计-服务端API与数据模型.md` §2.3：
`DELETE /kb/:kbId` 对记忆库返回 404，不作为清空通道。

`DELETE /memory/all` 契约（8 个端点中的第 8 个，登记见 `设计-服务端API与数据模型.md` §4）：

```
DELETE /memory/all      requireAuth
响应 204（幂等：无记忆库也返回 204）
行为：删除该 owner 记忆库下的全部 documents / chunks / chunks_fts（复用
      deleteMemoryDocuments），保留 knowledge_bases 中的记忆库行本身
      （懒创建的幂等键，删了会与 UNIQUE 索引的语义纠缠，没有好处）
```

清空后本地**不清除分界线** —— 分界线记录的是"这些轮次已归档过"这个历史事实，
与服务端是否还存有内容无关；清除它会把大量轮次放回发送 history，
正是 §5.2 要避免的。UI 在确认弹窗里说明「已归档的轮次不会重新加入对话」。

## 6. 设置存档 v6

> 本节所有 `MIN_THRESHOLD_PCT` / `MAX_THRESHOLD_PCT` / `DEFAULT_THRESHOLD_PCT`
> 均从 `src/lib/contextBudget.ts` 导入（见 `设计-上下文预算与覆盖入口.md` §2），
> 取值 40 / 90 / 70。**settingsBackup.ts 与 App.tsx 都导入这三个常量，不写字面量。**

### 6.1 `AppState` 新增字段（`src/types.ts`）

接在 `mcpToolsEnabled` 之后：

```ts
  /** Persistent memory master switch. Off by default — the feature stores
   *  distilled facts as plaintext on the server, so it must be opt-in. */
  isMemoryEnabled: boolean;
  /** Context-usage percentage that triggers the extraction prompt. Valid range
   *  is [MIN_THRESHOLD_PCT, MAX_THRESHOLD_PCT] from lib/contextBudget. */
  memoryThresholdPct?: number;
  /** Manual contextWindow overrides keyed by model id. inferLimits() only
   *  pattern-matches model names, which is not reliable enough to gate a
   *  feature on for self-hosted / proxied endpoints. */
  modelContextOverrides?: Record<string, number>;
  /** When the user accepted the plaintext-storage disclosure. Undefined = never
   *  shown; the dialog is gated on this rather than on isMemoryEnabled so that
   *  toggling off and on again does not silently skip the disclosure. */
  memoryDisclosureAcceptedAt?: number;
```

### 6.2 `DEFAULT_SETTINGS`（`App.tsx:361`）

```ts
  isMemoryEnabled: false,
  memoryThresholdPct: 70,
  modelContextOverrides: {},
  // memoryDisclosureAcceptedAt intentionally absent — undefined means
  // "disclosure not yet accepted".
```

### 6.3 `SCHEMA_VERSION` 与 IDB 迁移（`App.tsx:58`）

`SCHEMA_VERSION` **8 → 9**，加 `migrateV8ToV9`：

```ts
function migrateV8ToV9(raw: any): any {
  return {
    ...raw,
    isMemoryEnabled: false,
    memoryThresholdPct: 70,
    modelContextOverrides: {},
    _version: 9,
  };
}
```

并在 `migrate()`（`:60`）尾部加 `if (v < 9) raw = migrateV8ToV9(raw);`。

`setSettings({...})` 的加载块（`:526-627`）末尾追加四条读取，与既有风格一致：

```ts
  isMemoryEnabled:
    typeof parsed.isMemoryEnabled === "boolean"
      ? parsed.isMemoryEnabled
      : DEFAULT_SETTINGS.isMemoryEnabled,
  memoryThresholdPct:
    Number.isFinite(parsed.memoryThresholdPct) &&
    parsed.memoryThresholdPct >= MIN_THRESHOLD_PCT &&
    parsed.memoryThresholdPct <= MAX_THRESHOLD_PCT
      ? Math.floor(parsed.memoryThresholdPct)
      : DEFAULT_SETTINGS.memoryThresholdPct,
  modelContextOverrides:
    parsed.modelContextOverrides && typeof parsed.modelContextOverrides === "object" &&
    !Array.isArray(parsed.modelContextOverrides)
      ? parsed.modelContextOverrides
      : {},
  memoryDisclosureAcceptedAt:
    Number.isFinite(parsed.memoryDisclosureAcceptedAt)
      ? parsed.memoryDisclosureAcceptedAt
      : undefined,
```

阈值范围**必须**从 `contextBudget.ts` 导入 `MIN_THRESHOLD_PCT`（40）/ `MAX_THRESHOLD_PCT`（90），
**不得**在此处写死数字 —— 两处各写一套数字，将来改一处就会出现"存档接受但运行时被夹"的
不一致。低于 40 会在对话刚开始就触发，高于 90 来不及提炼就已超限。

### 6.4 `settingsBackup.ts` 三处（`EXPORT_VERSION` 5 → 6）

**① 版本号**（`:14-15`）

```ts
const EXPORT_VERSION = 6;
const SUPPORTED_IMPORT_VERSIONS = new Set([2, 3, 4, 5, 6]);
```

**② 校验**（接在 `if (obj._version >= 5) {...}` 块之后，比照 `:286` 的写法）

```ts
  // v6 fields: persistent-memory switch + threshold + context overrides.
  // Pre-v6 files lack them entirely — accepted and backfilled below.
  if (obj._version >= 6) {
    if (s.isMemoryEnabled !== undefined && typeof s.isMemoryEnabled !== "boolean") {
      issues.push("isMemoryEnabled 必须是布尔");
    }
    if (
      s.memoryThresholdPct !== undefined &&
      (typeof s.memoryThresholdPct !== "number" ||
        !Number.isFinite(s.memoryThresholdPct) ||
        s.memoryThresholdPct < MIN_THRESHOLD_PCT ||
        s.memoryThresholdPct > MAX_THRESHOLD_PCT)
    ) {
      issues.push(`memoryThresholdPct 必须是 ${MIN_THRESHOLD_PCT}-${MAX_THRESHOLD_PCT} 的数字`);
    }
    if (
      s.modelContextOverrides !== undefined &&
      (typeof s.modelContextOverrides !== "object" ||
        s.modelContextOverrides === null ||
        Array.isArray(s.modelContextOverrides))
    ) {
      issues.push("modelContextOverrides 必须是对象");
    }
  }
```

**③ backfill**（接在 v5 backfill 段之后，比照 `:368` 的写法）

```ts
  // --- v6 backfills: persistent memory ---
  // Old archives predate the feature; importing one must never silently turn
  // on plaintext server-side storage, so this defaults to false regardless.
  if (typeof filled.isMemoryEnabled !== "boolean") {
    filled.isMemoryEnabled = false;
  }
  {
    const pct = Number(filled.memoryThresholdPct);
    filled.memoryThresholdPct =
      Number.isFinite(pct) && pct >= MIN_THRESHOLD_PCT && pct <= MAX_THRESHOLD_PCT
        ? Math.floor(pct)
        : DEFAULT_THRESHOLD_PCT;
  }
  if (
    !filled.modelContextOverrides ||
    typeof filled.modelContextOverrides !== "object" ||
    Array.isArray(filled.modelContextOverrides)
  ) {
    filled.modelContextOverrides = {};
  }
  // memoryDisclosureAcceptedAt is deliberately NOT backfilled to a timestamp:
  // an imported archive must re-show the plaintext-storage disclosure.
  if (!Number.isFinite(filled.memoryDisclosureAcceptedAt)) {
    delete filled.memoryDisclosureAcceptedAt;
  }
```

### 6.5 不入导出（沿用 SSOT §9）

- 嵌入配置的 `base_url` / `api_key` / `model` —— 仅存服务端（KB 审计 D8）
- 记忆条目本身 —— 服务端按 session 生命周期管理
- `memoryDisclosureAcceptedAt` **入导出但不 backfill**，见上
