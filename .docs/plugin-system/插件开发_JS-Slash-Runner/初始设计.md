# NyaaChat扩展插件开发_JS-Slash-Runner
## 移植ST扩展插件酒馆助手（Tavern-Helper）中的JS-Slash-Runner层
- 严格分析探索ST扩展插件酒馆助手（Tavern-Helper）的功能
  - 酒馆助手是一个高度集成的重型框架，包括前端渲染、JS脚本库、JS脚本运行层（JS-Slash-Runner）、ST角色卡导入时自定导入JS脚本和正则、预设导入、变量层、语音播放、提示词注入等
  - 但以上功能中，前端预览、变量层、提示词注入都是NyaaChat自有实现过的功能，语音播放功能时之前开发过的引用朗读插件实现过的功能，会产生冲突，NyaaChat没有ST预设，这些都要避免迁移进NyaaChat
  - 实际需要迁移进NyaaChat的只有JS脚本运行层，以及角色卡导入时（ST角色卡和NyaaChat角色卡导入都需要）将角色卡自带的JS脚本导入的功能
  - 酒馆助手的变量层需要看一下，是不是ST自己的变量系统，NyaaChat的变量系统不是很完善，根据这一次工程，需要考虑是否重建NyaaChat的变量系统

## 核心目的
通过JS-Slash-Runner插件，让ST角色卡中基于JS脚本的MVU（Model-View-Update）体系脚本运行起来
- MVU（Model-View-Update）变量框架被做成JS脚本塞入酒馆助手是ST社区类脑的用户魔改行为，故此没有正式文档科参考，需要实际考察分析参考资料中提供的MVU脚本，从脚本业务逻辑上理解其原理，分析结束后需要在 H:\GitHub\NyaaChat\.docs\plugin-system\插件开发_JS-Slash-Runner 目录落下MVU的技术性说明文档
- 酒馆助手本身提供了一个带有UI的变量管理器，实际用户很少用到，NyaaChat中不需要提供这个UI
- 酒馆助手提供了脚本库的UI，用来显示脚本是否被启用、手动添加删除编辑JS脚本，以及ST角色卡导出时带上JS脚本，ST角色卡导入时自动导入JS脚本，切换不同角色卡时只显示和启用当前角色卡的JS脚本
  - NyaaChat扩展的JS-Slash-Runner插件需要这套功能，包括角色卡附带的JS脚本与角色卡一并导出、导入、自动切换（参考NyaaChat已经实现的`正则`功能），以及JS脚本的列表可见、启用禁用、删除，但NyaaChat不需要提供JS脚本在线编辑功能
- NyaaChat扩展的JS-Slash-Runner插件需要依照酒馆助手的JS-Slash-Runner层实现脚本可在前端状态层运行的业务功能，当前版本优先做到支持来自ST角色卡的MVU脚本+MVU_zod脚本的使用
  - NyaaChat中不需要提供用户创作开发MVU相关脚本的功能，但NyaaChat用户在使用角色卡时，如果打开NyaaChat扩展的JS-Slash-Runner插件添加了JS脚本，导出、上传、发布角色卡时，JS脚本应跟随角色卡作为角色卡json结构的数据一并导出，方便下载和被使用

## NyaaChat扩展插件 JS-Slash-Runner 的UI要求
- 参考酒馆助手`脚本库`界面的内容元素，但不要直接用ST扩展界面，保持ST扩展插件移植规范，以NyaaChat的UI/UX控件风格重构

## 变量系统优化
- NyaaChat自有一套简单的变量层，既没有用户可见的前端，也不是很完善，NyaaChat在产品页面中没有任何说明，尽在NyaaChat-Docs帮助文档中有用法说明
- 考察ST自身和酒馆助手的变量系统，考量NyaaChat变量功能的优化方案，以匹配MVU的使用
