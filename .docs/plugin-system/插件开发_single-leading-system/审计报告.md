## 2. 审计结论

**方案可以沿用原生插件框架实现，但现有框架不足以直接承载全部功能。** 需要新增通用出站处理接口与不含凭据的模型配置快照；宿主负责网络请求、结束状态判断和工具执行，插件负责模型选择与消息结构转换。D10 已撤销 thinking 控制设计，不再增加这类参数或 UI。

不能用现有世界书文本渲染器代替消息结构处理，也不能把插件代码直接写进 Ollama 分支。无需另建插件后端、数据库、nginx 转发或 Ollama 专用调用管线。

本轮已确认辅助调用排除、恢复仅限一次发送、整次最多一次、已有工具结果后禁止新工具执行；thinking 参数映射已取消。单独合并 system 不能解决截断和工具副作用问题，必须完成宿主执行链路接线。

### 3.1 框架规范中需按现代码解释的部分

框架规范部分主文仍保留早期行数、三种事件、唯一 quote-tts 等快照；现代码已有三个插件、更多事件及后补的叶子模块。采用该规范的依赖和生命周期约束，不照抄旧文件长度或将示例接口误当完整现状。

新增宿主叶子接口应在正式实现时同步登记到框架规范的导出面和偏差记录。不得为了新增本插件整体改写已有插件契约或清理无关历史文档。

### 3.2 UI 与依赖边界

- 继续使用扩展列表及详情页，插件没有独立入口、窗口或侧栏。
- 设置页警告对齐 `plugins/js-slash-runner/ScriptRunnerSettings.tsx:125` 及 `plugins/EJS-template/EjsTemplateSettings.tsx:487`：`AlertTriangle`、琥珀色背景与边框、圆角文本块，支持深浅色。
- 插件不值导入 `src/plugins/runtime`、`backend`、`registry`、聚合 `index`，也不引宿主组件或设置 store。
- 新增能力走 types 或只依赖类型的叶子模块；网络和执行器仍由宿主调用。
- 框架 backend 限制针对插件后端能力。本插件不新建 backend；已有对话供应商的用户自定义地址继续由宿主 API 层管理。

## 5. 本轮新增确认

### D7：静态 assistant 混排顺序（已确认）

2026-10-18，用户选择“接受：保留角色，调整顺序”。

```text
输入静态区：system A → assistant B → system C → assistant D
输出静态区：system(A + C) → assistant B → assistant D
随后接真实聊天历史、最新 user；动态尾按原约定折入最新 user。
```

system 内容按原相对顺序合并；assistant 保留角色、内容及彼此相对顺序。允许两类消息之间的局部先后变化，不提升 assistant 权限，不声称绝对语义无损。

### D8：逐供应商实例、逐模型配置（已确认）

2026-10-18，用户选择“采用逐模型配置”。

- 插件总开关默认停用；停用保留已保存配置。
- 启用插件后，在插件设置页逐个勾选模型；当时同意的逐模型 thinking 开关随后由 D10 撤销。
- 用供应商实例 ID 与模型 ID 联合区分，同名模型跨供应商互不影响。
- 不按 Qwen 名称自动匹配，不提供未经确认的全局自动套用。

### D9：首版网络协议范围（已确认）

2026-10-18，用户选择“首版支持 OpenAI 兼容接口”。

支持所有供应商分类中使用 OpenAI 兼容 Chat Completions 的模型，不以 Ollama 身份为启用条件。Anthropic 原生 `/messages` 首版不接入，保留原有 system 与缓存路径。该决定不等于这些网关均已完成真实连通性或 thinking 验收。

### D10：取消 thinking 控件与参数设计（已确认，覆盖 D2/D8 相应部分）

用户决定：“放弃 thinking 开关设计，保持开启，不在 NyaaChat 中提供 thinking 关闭能力”。不新增 thinking 开关、参数预设或任意 JSON 参数编辑器，也不自动关闭思考。NyaaChat 沿用服务端默认思考行为，不注入开启/关闭字段或预算；目标模型此前已验证默认开启。其他供应商的默认状态由部署侧保证，不能把“不发送关闭参数”宣传为能强制所有服务开启。

### D11：仅主对话（已确认）

主对话、新的重新生成请求及其工具续轮和自动恢复纳入；记忆提取、绘图提示词辅助、健康检查、模型列表和独立 ext-host 绘图代理保持原流程。

### D12：生效范围与恢复次数（已确认）

截断保护只在插件选中且实际生效的模型请求中启用。整次发送共用一次恢复机会，各工具轮次不分别获得一次。是否已有正文按当前这次模型请求判断：之前轮次的正文保留，当前请求已有任何展示文本则不自动重试。

### D13：已有工具结果后恢复只做汇总（已确认，修订 D5）

已有工具结果后的恢复保留原 assistant tool_calls 和全部对应 tool 结果，移除新工具声明，禁止新的工具执行。恢复响应若仍含 tool_calls，明确结束而不执行。因此未完成的多步工具任务可能无法继续，这是已接受的取舍。

该决定明确修订 D5 的“原参数不变”：允许移除工具声明，其他模型、部署预算、采样及 thinking 行为不变。尚未执行任何工具时，首次截断恢复可以保留原工具声明；完整合法响应才允许执行，不执行失败尝试中的残缺参数。

### D14：仅同一次发送内自动恢复（已确认，修订 D5）

不实现新的手动恢复按钮、跨发送或跨刷新恢复，不保存完整请求检查点。撤销“手动关闭 thinking 后重试也复用工具结果”的历史要求。现有“重新生成”仍是从头发起的新请求，可能重新调用工具，不能作为保留骰子结果的恢复入口。

### D15：失败与完成事件（已确认）

截断保留正文并标记错误；空回复、连接中断、工具参数不完整分别报错；用户停止不重试。失败或截断不触发回复成功完成事件，其正文中的 MVU 更新块不按成功回复处理。恢复成功只发一次完成事件。已经发生的 EJS 写入及工具副作用不回滚。

### D16：误开 AnswererFlagalac 时整轮不介入（已确认）

插件若匹配模型但检测到有效 AF 目标，本轮不做消息合并，也不启用本插件的恢复策略；沿用原请求流程，只记录不兼容原因。不自动关闭 AF、不删载荷、不弹窗、不阻止发送。目标模型仍可能返回原模板错误。

### D17：模型不可用时保留配置（已确认）

模型从供应商列表删除时保留插件配置，显示“当前不可用”且不生效，用户可手动移除。相同 provider.id＋model.id 恢复后沿用配置；不同供应商 ID 即使名称相同也不自动继承。

## 7. 技术方案与取舍

1. 新增 `src/plugins/outbound.ts` 叶子模块提供通用策略注册与解析；`src/plugins/modelContext.ts` 提供去凭据的模型展示快照。插件 setup 注册，停用清理。
2. 配置保存在插件 config 的模型数组中，不修改 ModelEntry、不新增存档版本。数组整体替换实现选择与移除，避免深合并导致删键残留。
3. 组装层新增带布局的入口并保留原数组入口；通过独立布局标明静态前缀、最新 user 和动态尾，不按内容标签猜测边界。
4. 主对话进入请求准备阶段时冻结一份策略快照；续轮、恢复使用同一份，新发送才重新解析配置。插件停用不会中途改变已经发送的一轮。
5. 策略一次性完成静态合并及动态尾折叠；宿主见到已处理结果即跳过旧尾折叠，随后各次发送只检查不变量，避免重复追加。
6. 结束状态与工具安全留在宿主，受通用策略控制，不硬编码插件 ID、Qwen 名称或 Ollama 分支。
7. 本插件生效时，MCP 工具成功日志带非助手完成标记；最终正常完成才触发一次 message:received。原有非目标路径保留当前行为，避免把准备任务扩大为全局事件系统重构。
8. 不增加 thinking 参数，不新增后端、数据库、nginx 或环境变量。复杂结构验收独立于健康检查。
