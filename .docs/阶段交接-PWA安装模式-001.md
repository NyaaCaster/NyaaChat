## 关键技术依据（非推测，均已实测抓取）

Chrome 可安装性最低要求（[Chrome for Developers](https://developer.chrome.com/docs/lighthouse/pwa/installable-manifest)）：
`name`/`short_name`、**同时含 192×192 与 512×512 图标**、`start_url`、
`display` ∈ {fullscreen, standalone, minimal-ui}、`prefer_related_applications` ≠ true，
且页面必须是**安全上下文（HTTPS 或 localhost）**。

参考站实证：`https://h.nyaa.host:43080/site.webmanifest` 字段与 `index.html` 的 meta 标签集合，
本实现与之对齐（`display: standalone`，按用户拍板）。

## 三个必须知道的部署事实（本轮踩过）

### 1. 🚨 HTTP 源永远不会弹安装提示

NyaaChat 原生产入口是 `http://h.nyaa.host:3095/`（**明文 HTTP**）。Chrome 只在安全上下文提供安装入口，
**只改前端代码在 HTTP 上完全不生效**。因此本轮新增了 macmini 的 HTTPS 入口 **43095**（TLS 终止后转发
3095）。43095 是 3095 的「43xxx HTTPS 孪生端口」，与 43080/43081 同一命名惯例。

- 证书：复用现有 LE SAN 证书（`h.hony-wen.com` + `h.nyaa.host`），**无需新证书、无需新 443 监听**。
- **无 Basic Auth**：NyaaChat 有自己的账号体系；且 Basic Auth 会破坏 Android 安装流程——独立窗口
  无法在每次导航时干净重放 Basic 凭据。
- 路由器需放行 TCP 43095 → `192.168.31.141`（本轮用户已放行；内网访问不需要）。

### 2. 🚨 SPA 回退会静默吞掉 manifest 与图标（实测复现）

`nginx.conf` 的 `location /` 是 `try_files $uri $uri/ /index.html`。改动前实测：

```
/site.webmanifest -> 200 text/html 1413B   ← 返回的是 index.html，不是 404！
/icons/pwa-192.png -> 200 text/html 1413B
```

**返回 200 而非 404**，极易误判为「文件没问题」。而 Chrome 要求 manifest 的 MIME 必须是
`application/manifest+json`，否则**直接忽略该 manifest**。修复即 `location = /site.webmanifest`
（精确匹配优先级高于前缀 `location /`）。

### 3. add_header 覆盖坑（K1 同类）

新 location 块一旦声明 `add_header`，server 级那一组安全头**全部失效**。故 manifest 块内复述了
CSP / X-Frame-Options / X-Content-Type-Options / Referrer-Policy / Permissions-Policy。
已实测确认 manifest 响应带全套安全头（无回归）。

### 4. 🚨 `theme-color` 必须是「背景色」而不是「品牌色」（真机反馈后修正）

**现象**：真机安装启动后，界面顶部有一条**蓝色横条**。

**定性**：这不是 bug，`display: standalone` 的语义就是「隐藏浏览器 UI、**保留系统状态栏**」，
那条横条就是 Android 系统状态栏。它被 `theme-color` **染色**。

**根因**：首版把 `theme-color` 设成了品牌蓝 `#2563EB` → 状态栏被涂成品牌蓝，
在浅色 UI 顶上形成一条突兀的蓝色带。

**修法**：`theme-color` 改用 **App 自身背景色**（浅 `#FCFCFD` / 深 `#0A0A0A`，与
`index.css` 的 `body` 和 `ChatInterface` 根容器一致），并**随主题动态同步**。

**权威佐证**：参考站 `h.nyaa.host:43080` 的 `theme-color` 是 **`#fafafa`**（它自己的**背景色**，
不是 OpenCode 品牌色），且用内联启动脚本按配色改写：

```js
var metas = document.querySelectorAll("meta[name='theme-color']")
if (metas.length > 0) metas[0].setAttribute("content", isDark ? "#080808" : "#fafafa")
```

**本实现的两段式策略（缺一不可）**：

1. `index.html` 内联脚本：只能读 `prefers-color-scheme`（用户**手动**主题存在 IndexedDB，
   无法在首屏前同步读取）→ 先猜一个值，**消除首帧闪错色**；并监听系统主题变化。
2. `App.tsx` 主题 effect：等真实主题确定后再精确同步（含**手动切换**），
   修正内联脚本猜错的情况。

> ⚠️ `LIGHT_BG`/`DARK_BG` 在 `src/lib/themeColor.ts` 与 `index.html` 内联脚本里**各有一份**。
> 这是本套 PWA 逻辑中**唯一**不可避免的常量重复（内联脚本必须早于 React 挂载运行）。
> 改一处务必同步改另一处，两处注释里都写了这条提醒。
